# Instrumentos da avaliação de usabilidade

Anexos prontos para juntar à submissão ao CEP (`docs/cep_submissao.md`) e para
usar na coleta. Derivados do desenho em `docs/avaliacao_usabilidade.md`. Campos
entre `[...]` são a preencher. **Nenhum número aqui é resultado** — são
instrumentos, não medições.

---

## Anexo I — Questionário de caracterização

Preenchido no início da sessão, antes das tarefas. Identificação apenas por código
(`P01`…`P20`); o nome não é registrado.

1. **Código do participante:** P[ ]
2. **Perfil no estudo:** ( ) Recepção ( ) Enfermagem ( ) Medicina ( ) Farmácia
   ( ) Gestão
3. **Situação:** ( ) profissional em exercício ( ) discente concluinte com estágio
4. **Tempo de experiência na função:** ( ) < 1 ano ( ) 1–3 anos ( ) 3–10 anos
   ( ) > 10 anos
5. **Você usa prontuário eletrônico hoje?** ( ) Não ( ) Sim — qual: [ ]
6. **Com que frequência usa computador/sistemas no trabalho?** ( ) Nunca
   ( ) Raramente ( ) Às vezes ( ) Com frequência ( ) Sempre
7. **Autoavaliação de facilidade com tecnologia** (1 = muita dificuldade,
   5 = muita facilidade): ( )1 ( )2 ( )3 ( )4 ( )5

## Anexo II — Escala de Usabilidade do Sistema (SUS)

Aplicada ao final da sessão. Dez itens, alternando afirmações positivas e
negativas, em escala de 1 (**discordo totalmente**) a 5 (**concordo totalmente**).
Peça que responda a todos, sem deixar em branco; se hesitar, marque o ponto do
meio.

> **Nota de origem.** A SUS é de Brooke (1996). A versão em português do Brasil a
> citar é a **adaptação transcultural validada** de LOURENÇO, CARMONA e LOPES
> (Aquichan, v. 22, n. 2, e2228, 2022; DOI 10.5294/aqui.2022.22.2.8), com estrutura
> unidimensional e alfa de Cronbach 0,76. A redação dos dez itens abaixo deve ser
> **conferida item a item contra essa fonte** antes de aplicar — o texto aqui é
> base de trabalho, e a versão publicada é a autoridade.

| # | Afirmação | 1 | 2 | 3 | 4 | 5 |
|---|---|:-:|:-:|:-:|:-:|:-:|
| 1 | Acho que gostaria de usar este sistema com frequência. | | | | | |
| 2 | Considerei o sistema mais complexo do que precisava ser. | | | | | |
| 3 | Achei o sistema fácil de usar. | | | | | |
| 4 | Acho que precisaria de apoio de alguém com conhecimento técnico para conseguir usar este sistema. | | | | | |
| 5 | Considerei que as várias funções do sistema estavam bem integradas. | | | | | |
| 6 | Achei que havia inconsistência demais neste sistema. | | | | | |
| 7 | Imagino que a maioria das pessoas aprenderia a usar este sistema rapidamente. | | | | | |
| 8 | Considerei o sistema muito difícil de usar. | | | | | |
| 9 | Senti-me muito confiante ao usar o sistema. | | | | | |
| 10 | Precisei aprender muitas coisas antes de conseguir usar este sistema. | | | | | |

**Cálculo do escore (0–100), feito depois, não na frente do participante.**
- Itens **ímpares** (1,3,5,7,9): contribuição = (valor marcado − 1).
- Itens **pares** (2,4,6,8,10): contribuição = (5 − valor marcado).
- Some as dez contribuições (0–40) e **multiplique por 2,5**.
- Referência de leitura: ~68 é a média usual; abaixo disso, abaixo da média. A
  interpretação por faixa adjetiva (Bangor) e por perfil vai na análise.

## Anexo IV — Roteiro do moderador

**Antes de começar.** Instância de demonstração reposta ao estado inicial; conta do
perfil já logada ou credenciais à mão; gravação de tela e áudio pronta; TCLE
assinado; questionário de caracterização preenchido.

**Fala de acolhimento (ler).**
> "Obrigada por participar. Hoje quem está sendo avaliado é o **sistema, não você**
> — não existe resposta certa ou errada, e os pacientes são fictícios. Vou pedir
> que você **pense em voz alta** enquanto usa: diga o que está procurando, o que
> espera que aconteça e o que te confunde. Não vou poder ajudar durante as tarefas,
> para medir como o sistema se explica sozinho — mas você pode parar qualquer
> tarefa ou a sessão a qualquer momento, sem problema. Podemos começar?"

**Instrução de pensar-alto.** Se o participante silenciar por muito tempo, apenas:
"o que você está pensando agora?" — nunca sugira o caminho.

**Regra de intervenção.** Não intervenha antes de **[3] minutos** de tentativa
genuína ou de pedido explícito de ajuda. Se intervier, **registre como
assistência** e anote o ponto exato. Assistência conta contra a eficácia da tarefa
— é dado, não fracasso da sessão.

**Por tarefa.** Leia o cartão (Anexo V) em voz alta ou entregue impresso; marque
início e fim; observe sucesso/erro/assistência/incidente na planilha (Anexo VI);
aplique o SEQ ao terminar.

**Encerramento — entrevista semiestruturada (ler e conversar).**
> - O que foi mais fácil? E mais difícil?
> - Teve algum momento em que o sistema fez algo que você não esperava?
> - Em algum ponto você não entendeu **por que** não conseguiu fazer algo? (sondar
>   as negações: dado de outra unidade que não apareceu, valor recusado, aviso de
>   envio simulado)
> - Se pudesse mudar uma coisa, qual seria?
> - Algo que faltou e que você esperava encontrar?

**Fala de fechamento.** Agradeça; ofereça a devolutiva dos resultados; confirme os
canais de contato do TCLE.

## Anexo V — Cartões de tarefa (por perfil)

Cada cartão traz o que o **participante** lê (Cenário/Tarefa) e, separado, o que só
o **moderador** vê (Critério de sucesso / Caminho esperado / Observar). A tarefa de
aquecimento abre toda sessão e **não é pontuada**.

**Aquecimento (todos).**
*Tarefa (participante):* "Entre no sistema com a conta que preparei e encontre a
sua área de trabalho." *Moderador:* só para dissipar o primeiro contato; não
pontuar.

### Recepção

**R1 — Cadastrar paciente.**
*Cenário/Tarefa:* "Chegou um paciente novo. Cadastre-o com os dados deste cartão
[nome fictício, data de nascimento, CPF e CNS válidos fornecidos]."
*Critério de sucesso:* cadastro criado e localizável na busca.
*Observar:* reação à validação de CPF/CNS; entende as mensagens de campo
obrigatório?

**R2 — Localizar paciente.**
*Tarefa:* "Encontre o cadastro do paciente [nome de um já semeado] e abra-o."
*Sucesso:* abriu o cadastro certo pela busca com sugestão.
*Observar:* usa a busca com sugestão ou procura em lista? a sugestão (nome, CNS,
idade) basta para desambiguar?

**R3 — Agendar atendimento.**
*Tarefa:* "Agende um atendimento para esse paciente."
*Sucesso:* agendamento criado.

### Enfermagem

**E1 — Triagem de Manchester.**
*Tarefa:* "Realize a triagem deste paciente registrando os sinais vitais deste
cartão [valores plausíveis] e a queixa [ ]."
*Sucesso:* triagem salva com classificação de risco.
*Observar:* as cores do protocolo são claras? a ordem dos campos ajuda?

**E2 — Sonda de plausibilidade (o valor impossível).**
*Tarefa:* "Ainda nesta triagem, registre a altura do paciente: **172** no campo de
altura."
*Sucesso:* o participante **percebe a recusa** do valor impossível (172 m) e o
corrige para o valor plausível (1,72 m). *Observar:* a mensagem explica **por
quê**? a pessoa lê como defeito ou como conferência? **É a sonda da PP5** — anote a
reação literal.

### Medicina

**M1 — Evolução no prontuário.**
*Tarefa:* "Abra o prontuário do paciente [ ] e registre a evolução: [texto curto]."
*Sucesso:* evolução gravada e visível no prontuário longitudinal.

**M2 — Prescrever e assinar.**
*Tarefa:* "Prescreva [medicamento] e **assine** o documento."
*Sucesso:* documento assinado. *Observar:* a busca de medicamento (apresentação,
via) basta? o passo de assinatura é compreendido?

**M3 — Reconhecer o envio à RNDS.**
*Tarefa:* "O que aconteceu com o envio deste documento à rede nacional?"
*Sucesso:* reconhece que foi **enfileirado em modo simulado** (a tela avisa).
*Observar:* **sonda da PP5** — a pessoa entende que nada saiu de verdade, ou supõe
que transmitiu?

### Farmácia

**F1 — Dispensar item.**
*Tarefa:* "Dispense o item prescrito para o paciente [ ]."
*Sucesso:* dispensação registrada.

**F2 — Consultar estoque.**
*Tarefa:* "Confira o estoque resultante desse item."
*Sucesso:* localizou o saldo atualizado.

### Gestão

**G1 — Relatório e exportação.**
*Tarefa:* "Abra o relatório de produção e exporte os dados em CSV."
*Sucesso:* relatório aberto e arquivo CSV exportado.

**G2 — Sonda do isolamento (o limite compreensível).**
*Cenário:* a conta usada tem alcance de **uma unidade**.
*Tarefa:* "Tente encontrar um atendimento realizado em **outra** unidade da rede."
*Sucesso (do estudo, não da tarefa):* observar se a ausência do dado é lida como
**limite compreensível** ou como **defeito**. *Observar:* **sonda da PP5** — a tela
declara o próprio recorte; a declaração funciona para quem não a escreveu? Anote a
interpretação da pessoa.

## Anexo VI — Planilha de coleta

Uma linha por (participante × tarefa).

| Participante | Tarefa | Resultado | Tempo (s) | Nº erros | Nº assistências | SEQ (1–7) | Incidentes observados |
|---|---|---|---|---|---|---|---|
| P01 | R1 | sucesso / com assistência / falha | | | | | |
| … | | | | | | | |

**Resultado:** *sucesso* (sozinho), *com assistência* (moderador interveio),
*falha* (não concluiu). **Tempo:** do fim da leitura do cartão ao critério de
sucesso. **Erro:** ação que afasta do objetivo. **Incidente:** travamento, surpresa
ou fala reveladora, transcrita.

---

### Como estes instrumentos entram na análise

- **SEQ e tempo** localizam a dificuldade **na tarefa**; **SUS** resume a **sessão**.
- Tempos vão para a análise em **mediana e amplitude interquartil**, como o resto
  das medições do projeto — média esconde a dispersão.
- Os **incidentes** das sondas de PP5 (E2, M3, G2) são o material que diz se as
  **negações do sistema** — recusa de valor impossível, aviso de simulação, recorte
  territorial — se explicam para quem não escreveu o código. É a heurística 9 posta
  à prova por usuário real, e o ponto onde usabilidade encontra a segurança que é o
  centro do trabalho.
